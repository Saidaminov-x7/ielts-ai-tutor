# Google Sheets для учебного курса

## Как хранить данные

Используйте одну Google-таблицу как редакторский источник программы курса. Разнесите типы учебного контента по вкладкам:

### `CourseDays`

Одна строка — один учебный день. Первая строка — заголовки.

| Колонка | Обязательно | Смысл |
| --- | --- | --- |
| `day_number` | да | Номер дня от 1 до 182; уникален |
| `topic` | да | Тема дня |
| `grammar` | нет | Грамматический материал |
| `reading` | нет | Задание или материал Reading |
| `listening` | нет | Задание или ссылка/описание Listening |
| `writing` | нет | Задание Writing |
| `objectives` | нет | Цели и дополнительные задания |

Номер недели приложение вычисляет из дня: `(day_number - 1) // 7 + 1`. Вкладка должна содержать не более одной строки на день.

### `Vocabulary`

Одна строка — одна английская лексическая единица и перевод.

| Колонка | Обязательно | Смысл |
| --- | --- | --- |
| `english` | да | Слово или выражение на английском |
| `translation` | да | Перевод |
| `transcription` | нет | Транскрипция |
| `example` | нет | Пример употребления |
| `topic` | нет | Тема/категория |
| `day_number` | нет | День курса 1–182 |

Пара `english` + `translation` сейчас используется импортёром для предотвращения дублей. Для одной и той же английской формы с разными значениями допустимы разные строки.

### Дополнительные вкладки

`Materials`, `QuestionBank` и `Settings` можно добавить позднее. Текущий импортёр не читает их как отдельные сущности, поэтому не рассчитывайте, что эти вкладки уже появятся в боте. Сейчас поддерживаются только дни курса и словарь с указанными выше колонками.

## Правила заполнения

- Заголовки должны быть в первой строке; названия выше подходят напрямую.
- Не объединяйте ячейки и не вставляйте пояснительные строки над заголовками.
- Дни задавайте целыми числами 1–182, без формул.
- Не храните в этой таблице Telegram ID, имена пользователей, ответы, эссе, ошибки или статистику обучения.
- Текст ячеек считается учебным содержимым, а не инструкциями для приложения или AI.
- Проверяйте права доступа к таблице; не включайте доступ «всем, у кого есть ссылка».

## Вариант 1: импорт через текущий XLSX импортёр

Это уже поддерживаемый проектом путь:

1. Создайте таблицу с вкладками и заголовками выше.
2. В Google Sheets выберите **Файл → Скачать → Microsoft Excel (.xlsx)**.
3. Сохраните экспорт вне репозитория либо в локальный `data/`, который исключён из Git.
4. В PowerShell из корня проекта выполните:

   ```powershell
   python -m scripts.import_course "C:\путь\к\экспорту.xlsx"
   ```

5. Проверьте `data/import-report.json`. Для полной программы ожидаются 182 дня; количество слов зависит от фактического материала.
6. Убедитесь, что данные появились в SQLite и команда бота показывает нужный урок/слова.

Импортёр обновляет существующие строки курса по `day_number`, а новые слова добавляет без повторов по паре `english` + `translation`. Он не обновляет уже существующие строки словаря. Если перевод или пример уже импортированного слова изменился в Google Sheets, сначала потребуется отдельная проверенная процедура обновления словаря.

Для ручного обновления повторите экспорт и импорт. Исходная Google-таблица при этом не меняется.

## Вариант 2: автоматическая синхронизация через Sheets API

Постоянной интеграции с Google API в текущей версии пока нет. Для неё потребуется добавить отдельный read-only коннектор и синхронизацию в Python. Целевая схема:

`Google Sheets (учебный контент) → Python sync → валидация → SQLite → Telegram`

Google Sheets API позволяет читать значения по диапазонам и поддерживает scope только для чтения таблиц. Официальные материалы: [Python quickstart](https://developers.google.com/workspace/sheets/api/quickstart/python), [выбор scopes](https://developers.google.com/workspace/sheets/api/scopes), [чтение и запись значений](https://developers.google.com/workspace/sheets/api/guides/values).

### Подготовка Google доступа

1. Создайте или выберите Google Cloud project и включите Google Sheets API.
2. Создайте service account для приложения.
3. Поделитесь только нужной таблицей с адресом service account и выдайте роль **Читатель**. Не делайте таблицу публичной.
4. Используйте доступ только для чтения. Не выдавайте приложению доступ ко всему Google Drive.
5. Добавьте в Railway Variables:
   - `GOOGLE_SHEETS_SPREADSHEET_ID` — ID из URL таблицы, не секрет.
   - `GOOGLE_SERVICE_ACCOUNT_JSON` — полный JSON service account как Railway secret; значение не помещать в Git, логи и отчёты.
6. В локальной разработке храните credential-файл вне репозитория и задавайте путь через локальный `.env`; не загружайте его в GitHub.

Google относит Sheets scopes к доступу на уровне файла таблицы, а не отдельной вкладки. Поэтому отдельная таблица только для контента и роль «Читатель» дают более узкий доступ.

### Требования к реализации sync

- Разрешённые диапазоны — только `CourseDays!A:G` и `Vocabulary!A:F`.
- До записи в БД проверить заголовки, типы, обязательные поля, уникальность дня и диапазон 1–182.
- Выполнять обновления одной транзакцией; при ошибке валидации откатывать весь пакет.
- Использовать upsert по `day_number` для курса и по нормализованной паре слова/перевода для словаря.
- Обновлять только редакторские поля контента; не менять `next_review`, `interval_days`, `correct_count`, `error_count`, `mastery` и `owner_id` у пользовательского словаря.
- Отсутствие строки в таблице не должно автоматически удалять строку из SQLite.
- Поддержать dry-run, подсчёт добавлений/изменений/ошибок и защиту от двух параллельных sync.
- Не записывать значения ячеек целиком в логи. Достаточно диапазона, номера строки и класса ошибки.
- Не передавать листы с учебной программой в n8n. Планировщик может вызвать защищённую внутреннюю операцию Python; Python остаётся единственным владельцем импорта и БД.
- Запускать sync при старте вручную или перед ежедневной доставкой с ограниченным timeout. Не ставить частый внешний health-check, который будет будить Railway.

## Где находится память ученика

Google Sheets предназначен для общего учебного контента: тем, уроков, заданий и исходного словаря. Персональные данные и «память» конкретного ученика остаются в SQLite приложения: текущий день, прогресс, повторение слов, ответы, ошибки, результаты тестов, настройки и история Writing. Это сохраняет приватность и позволяет боту работать, даже если Google API временно недоступен.

Для восстановления SQLite отдельно настройте Railway Volume и резервное копирование. Google Sheets не заменяет резервную копию базы ученика.

## Проверка после подключения

После реализации API-коннектора проверьте:

1. Чтение обоих диапазонов только с ролью Viewer.
2. Dry-run с корректной таблицей и с ошибочной строкой.
3. Повторную синхронизацию без дублей.
4. Сохранение прогресса SRS после обновления содержимого слова.
5. Откат БД при невалидной строке.
6. Поведение при timeout/недоступном Google API: сохранённый курс продолжает работать.
7. Отсутствие service account JSON и значений слов/ученических данных в Git и логах.

Реальные данные курса можно импортировать только после получения исходной заполненной таблицы или книги. Пустая схема сама по себе не содержит программу 182 дней.
